# V2.1 — Zoho CRM · dialer recordings · training lock (2 Nov 2026)

Only these three changes; everything else (pages, flows, webhook CRM connector, uploads) behaves as before.

## 1. Zoho CRM (`/crm` → Zoho CRM card, customer profiles)
- **Connect:** an admin picks the Zoho data centre and approves access (OAuth, `access_type=offline`). Scopes: read Contacts,
  Leads, Deals; read/write Notes and Calls; read user and org. One connection per organisation; refresh and access tokens
  AES-256-GCM encrypted with `FIELD_KEY`; the callback checks an HMAC state held in an HttpOnly cookie, the same admin, and a
  genuine `accounts.zoho.*` server.
- **Customer profile:** the caller's Zoho Contact (or Lead), matched by phone and then remembered (`customers.zoho_id`), with
  Deals, Calls and Notes, read live, and "Open in Zoho".
- **Import:** Contacts / Leads → customer profiles (matched on mobile; records without a phone are skipped; nothing deleted).
- **Write-back:** after each analysed call, a Note with the summary, scores and a link to the call, plus (setting) a Call
  activity with type, start, duration and summary. Every attempt is in the sync log; failures never block the analysis.
- **Operator setup:** a *Server-based* client in api-console.zoho.com, redirect URI `<PUBLIC_APP_URL>/api/crm/zoho/callback`,
  multi-DC enabled → `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET` in the server env. Until then the card says "not configured".

## 2. Dialer recordings without manual upload (`/sources` — Dialer integration)
- A source per calling platform: Exotel, Ozonetel, Tata Smartflo, Knowlarity, MyOperator, or Generic. Each has a private
  webhook URL `/api/ingest/<id>?token=…` (or `Authorization: Bearer`), shown once and stored hashed.
- Accepts JSON, form-encoded, multipart (recording as a file) and GET query parameters. Answers 202 at once; the recording
  is then downloaded (https only, private / loopback addresses refused, ≤ 150 MB, 120 s, credentials never follow a redirect to
  another host), named `YYYYMMDD-CALLID_MOBILE_AGENT_CAMPAIGN-auto.ext`, and queued exactly like an upload → call-processing flow.
- Retries of the same call ID are ignored. Unanswered calls (no recording) are marked skipped. Failed events can be retried.
- **Agents:** a dialer's agent identifier is matched to an agent code, a **Dialer ID** (Team & roles → Agents) or an email;
  an unknown identifier becomes a new agent the admin is prompted to map.
- **Presets are starting points** — provider accounts rename fields. The mapping is editable, and the event log lists the field
  names (never values) each dialer actually sent. Optional "Recording download" credentials (`user:password` or `Bearer …`),
  encrypted, for hosts like Exotel that protect recording URLs.

## 3. Training lock and Team Leader "Done"
- No training test. While an agent (own-scope role) has any assignment that is not Done, their dashboard is **locked**: every
  page except Training, Profile and Notifications redirects to Training; the sidebar shows only Training; recordings and call
  APIs answer 423; Server Actions other than training updates are refused. Enforced on the server, not only in the UI.
- The agent can set progress (Assigned / In Progress) and leave notes; they cannot complete it.
- The team leader (any user with "Assign training" over that agent) uses **Done** on the assignment, with an optional review
  note. It records who and when; when it was the agent's last open training, the dashboard unlocks at the next request and the
  agent is notified ("Your dashboard is unlocked").

## Not verified yet
- Against a **real Zoho account** (needs the operator's client ID/secret): field names follow Zoho CRM API v8; confirm the
  Calls activity fields and the related-list names on the first live connection.
- Against **real dialer accounts**: the preset field maps follow each provider's published webhook shape and must be checked
  with one live call per provider (the event log shows what arrived).
- Background processing uses `after()` in a long-running Node server (CP Portal); a serverless host would need a queue.
- DNS rebinding between the address check and the download is not prevented (known limitation of the SSRF guard).
